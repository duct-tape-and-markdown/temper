# One job, one home

- A job the tree already performs is extended where it lives, never
  reimplemented beside itself. Before adding a function, module, or helper,
  search for the existing surface; the priority is delete or subsume, then
  extend the existing surface, then generalize a near-duplicate, then —
  last — add new.
- A new surface beside a near-duplicate names, in the commit body, the
  existing surface considered and why it did not fit.
- A second implementation of one job — two matchers, two normalizers, two
  encoders — is residue, fileable against this section whenever no pending
  entry consolidates it.
- A fact some data already carries is never spelled again by hand. A hand
  spelling beside its source is the same residue, and it folds into a
  derivation.
- Consolidation is a byproduct of the loop. Every neighborhood a change
  touches is swept against this page, and the residue found there is
  filed as a fold. A fold keeps the behavior its pinned tests hold, and it
  lands net-negative in the domain it folds.
- Test scaffolding is a surface too: shared fixtures and builders live in
  one home (`tests/it/common`), never copy-pasted per file.

**Tell:** two functions doing one job under different names; a count or list
in prose that a structure already knows ("seven families"); a value built by
hand beside its builder; a "keep in sync" or "mirror of" comment, which is
usually a downgrade's tell. **Held by:** the sweep's read, which is review.
