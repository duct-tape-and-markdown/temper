# `extend` lets the compiler refuse a subkind that drops its base's surface

0094 binds every selection of the base to the subkind, so a subkind must be substitutable for its base. `extend(base: KindDefinition<any>, delta)` (`sdk/src/kind.ts`) lets a subkind's surface `T` drop or retype a base field, and nothing refuses that until a base clause misfires at check. Type it as `extend<B extends object, T extends B>(base: KindDefinition<B>, delta: KindExtension<T>)`, so `tsc` (which emit now runs, 0098) refuses it at authoring. This is SDK-only: pin it with an SDK type test (`@ts-expect-error` on a narrowing subkind) and no `tests[]` line (PROTOCOL, Tests). Also add one sentence to the `.temper/**` SDK counsel rule (7f280c31): a field interface, clause set or guidance shared across kinds is an ordinary TS value spread into each kind's `extend` delta. That is a documented idiom, not an API.
