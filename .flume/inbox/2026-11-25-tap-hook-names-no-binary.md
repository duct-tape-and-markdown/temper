# A synthesized tap hook runs a bare `temper`, so off the PATH it exits 127, with no way to state the binary

Observed on the dogfood after GH #67. Its gate hooks now state `binary: ".temper/node_modules/.bin/temper"`, and temper is not on this machine's PATH. The tap hooks that a telemetry verifier synthesizes still render `temper tap "$CLAUDE_PROJECT_DIR"` (`TAP_COMMAND`), so every `InstructionsLoaded` and `PostToolUse` `Skill` tap exits 127, and the telemetry the `context-arrives` requirement rests on never records. This is the #65 gap again on the hook temper writes itself. The gate hook got a binary fact (0082) and a project anchor (0086); the tap hook has neither.

Sources: `specs/model/pipeline.md`, "Telemetry" (a telemetry declaration projects as tap hook registrations); 0082 (a hook that runs temper states the binary it runs); 0078 (one fact, one spelling). A harness that states its binary once should have every hook that runs temper use it. That raises a question for plan: whether the binary stays a per-gate-hook fact (0082 rejected a harness-wide field) or the tap borrows the gate hooks' fact. That is a spec question to raise, not to settle in build.
