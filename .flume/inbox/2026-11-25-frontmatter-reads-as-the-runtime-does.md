# A frontmatter scalar Claude Code accepts is a load fault in temper (55 members on one real harness)

From a stranger-gate probe of a large real harness (temper 0.0.25, owner-approved and reported abstractly). It produced `member.load-fault` ×55 (48 commands, 7 skills). Every one has an unquoted `description:` containing `": "`. Strict YAML rejects that, but Claude Code accepts it: in a lab on Claude Code 2.1.x (`claude -p --setting-sources project`), a skill of that shape was listed with its full description, quoted back verbatim (observed 2026-11-25; UNVERIFIED in the docs). The fault also cascades: 131 of 168 `supporting-doc.degree` findings are docs of those 7 skills, which lose all incoming links once the entry fails to load.

temper is reporting a file as unloadable when the runtime loads it. That is a false claim, not a strictness choice. `specs/builtins.md`: a kind's format facts are the harness's documented truth. `specs/model/representation.md`, "kind": a file format's reader is the lenient face and declares the leniency it forgives. Read frontmatter the way Claude Code does for the scalar shapes it accepts, and declare that leniency. Where the bytes are not portable YAML, that is at most an advisory naming the portability, never a load fault. Verify the runtime's actual parser behavior first, then cite it. Acceptance: an unquoted `description: a: b` loads as the member, and its supporting docs keep their degree.
