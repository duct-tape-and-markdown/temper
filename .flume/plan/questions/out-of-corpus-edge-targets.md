# How does an edge treat a target the runtime answers from outside the corpus?

Driver: OUTPUT-STYLE-IS-SELECTED-BY-SETTINGS. The runtime resolves some edge targets the harness tree cannot show: built-in styles (`default`, `Proactive`, …), user-scope styles under `~/.claude/output-styles`, plugin-provided styles, and user-scope marketplaces behind `installed-plugin`. The code ships a `provided` edge fact (a listed name neither resolves nor dangles). `specs/model/contract.md` "edge" does not name it. Every other off-tree target reads as dangling at error, so a `settings.local.json` naming a personal style is a false error.

Classes 0101 (a built-in reads as the runtime reads) and 0103 (a finding is true for its reader) both bear on this and do not decide it. Options: (a) record `provided` in "edge" and keep off-tree targets dangling; (b) a target the tree cannot decide collapses to one coverage note (0103's collapse rule), at least from `settings-local`, the local-locus member; (c) a per-edge severity for unresolved-by-scope. Plan leans (a)+(b): `provided` is a closed set the docs name, and an off-tree target is a mode the gate cannot decide. A ruling is a human `specs:` edit to contract.md "edge".
