# Where does an unrepresented harness's schema modeline point?

`specs/distribution.md`, "The placements and their enforcement modes", Keystroke: "Unrepresented, `temper schema` generates a JSON Schema … wired via the `yaml-language-server` modeline `install` places." Install places none when representation is declined (`src/install.rs:1150`). The represented modeline points at `.temper/schema/<kind>.json` and lands only once that file exists (`src/install.rs:1367`: "a modeline pointing at nothing is worse than no modeline"). But a declined install creates no `.temper/` (`specs/model/adoption.md`, "Install"; `tests/it/install.rs::declining_wires_the_session_start_reporter_alone_and_never_creates_temper_dir`).

So the schema has no home: (a) a committed schema path outside `.temper/`, which `temper schema` writes and install then references; (b) a published URL per engine version, which needs no file but needs network and a hosting promise (`specs/distribution.md`, "Versioning"); (c) the modeline stays a represented-only placement and the Keystroke claim is amended. Recommendation: (b), since it writes nothing to an unrepresented tree beyond the modeline itself. It needs a human ruling on hosting. Raised by inbox 2026-11-26-unrepresented-schema-modeline.
