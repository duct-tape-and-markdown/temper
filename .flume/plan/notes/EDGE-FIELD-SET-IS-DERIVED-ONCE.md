# EDGE-FIELD-SET-IS-DERIVED-ONCE: three folds landed, SDK tool address left

Folded: `drift::edge_fields_by_kind` is the one assembly-edge derivation;
`CustomKind::edge_field_slots(assembly)` composes it with relationships and
`satisfies`; `drift::layout_edge_fields` and compose's lenient copy are gone.
`body_fenced_blocks` runs on `track_fence`. install's two stem-ordinal loops
share `unclaimed_stem` (a hoisted settings module colliding on disk is now
`settings-2`, not `settings-1`, matching module_stems).

Already folded on this tree: emit.ts carries no local `hostAddress`; drift's
manifest label already routes through `ownerless_manifest_label`.

Left, not one job: SDK `toolAddress` (`root/tool/<name>`) vs
`memberAddress(tool)` (`tool:<name>`). memberAddress is the twin of the
engine's `payload_member_address`, which keys a tool member `tool:<name>` on
the seam (payload members, edge-target table, declared-address set). Making it
root-hosted-aware moves a tool's identity on both sides at once and needs
member-address.ts to learn `ROOT_HOSTED_KINDS` (it sits below builtins.ts).
That is an identity decision: which address a tool member wears everywhere.
The requirement runner row (`nestedAddress(ROOT_ADDRESS, requirement.key, …)`)
is the same family. A plan entry that rules on root-hosted identity owns it.
