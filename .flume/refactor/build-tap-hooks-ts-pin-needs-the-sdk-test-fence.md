## Surface

`TELEMETRY-EVENT-HOOK-TABLE-CROSSES-THE-GENERATED-SEAM` named three tests; its
fence admitted two. The third — `sdk/test/builtins.test.ts`, "the generated
table is non-empty and every name in it resolves to a non-empty event and
matcher" — is unlanded, because that path is in neither `files[]` nor the
effective fence (only `sdk/src/**` members were listed), and one path outside
the fence reverts the commit whole.

The engine-side equivalents shipped: `src/builtin_kind.rs`
(`every_tap_event_binds_a_non_empty_hook_registration`) pins the table's rows
non-empty and congruent with `tap::documented_event_names()`, and
`tests/it/seam_bindings_current.rs` pins every row into the generated bytes.
What is still unpinned is the TS side: that
`sdk/src/generated/tap-hooks.ts` imports and that `TELEMETRY_EVENT_HOOKS`
resolves off it at runtime — the one assertion the Rust gates cannot make.
